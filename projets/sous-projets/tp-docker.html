Conteneurisation Docker.

Virtualisation Légère / Web Server / DevOps

1. Contexte du Projet

Dans le cadre de mon module d'Administration Système, j'ai exploré la technologie Docker sous Linux Debian. Contrairement aux machines virtuelles classiques, Docker permet d'isoler des applications dans des environnements légers. Ma mission était de déployer, configurer et sauvegarder un serveur web personnalisé pour comprendre la flexibilité des micro-services.

2. Travail Fourni

A. Installation & Premier Déploiement

Après avoir installé le moteur Docker sur ma machine Debian, j'ai déployé mon premier conteneur basé sur l'image officielle httpd (Apache).

Comme le montre ma capture d'écran, j'ai utilisé la commande docker run pour mapper le port 8080 de ma machine vers le port 80 du conteneur. J'ai ensuite vérifié le bon état de santé de mon instance avec docker ps pour m'assurer que le service tournait correctement en arrière-plan.

Lancement et vérification des conteneurs actifs

B. Personnalisation du Serveur HTTP

Une fois le serveur opérationnel, je l'ai personnalisé pour qu'il diffuse mon propre contenu. Je suis entré au cœur du conteneur pour modifier le fichier index.html original.

J'ai remplacé le message générique par "Le site de Semih". Pour immortaliser cette modification, j'ai effectué un docker commit, créant ainsi une nouvelle image de conteneur incluant mon site web, prête à être exportée ou redéployée ailleurs.

Rendu du site personnalisé via localhost:8080

C. Administration Réseau & Bridge

J'ai approfondi la gestion réseau en créant un Bridge personnalisé. Cela m'a permis d'isoler mes conteneurs dans un sous-réseau privé où ils peuvent communiquer entre eux par nom d'hôte, simulant ainsi une architecture multi-services sécurisée. 


# Inspection de mon réseau personnalisé
$ sudo docker network inspect mon_reseau_prive

3. Difficultés Rencontrées

Ma principale difficulté a été de comprendre la persistance des données. J'ai appris que sans un commit ou l'utilisation de volumes, toute modification du site web disparaissait à la suppression du conteneur. J'ai aussi dû apprendre à manipuler l'interface en ligne de commande de Docker pour diagnostiquer les erreurs de connectivité entre réseaux.

4. Résultat Final

Je maîtrise désormais le cycle de vie des conteneurs, de l'image de base à la sauvegarde personnalisée. Je suis capable de transformer n'importe quel service en une instance légère et portable. C'est une compétence cruciale qui termine mon expertise en infrastructure.
